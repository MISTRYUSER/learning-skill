# 真实长期学习验证

仅在用户请求验证学习效果时使用，不把普通学习升级成研究项目。

## 两类证据分开

- 自动化多轮、跨会话与时间推进测试：证明助手是否按规则教学、存状态及排复习。
- 真实学习者的闭卷回忆与新场景任务：测量人的保持与迁移。需要实际参与和实际时间经过。

不能把模拟用户、修改系统时钟、评测代理答题或定时任务运行，写成真实学习者的成功。

## 最小前瞻性设计

1. 与用户确定主题和是否愿意做对照；默认一个主题、3个知识点。先冻结独立验收标准和记录格式，再开始教学。
2. T0先测已有水平，记录不知道、回答错误与已有能力；没有回答就保持 `pending_baseline`，不生成成绩。
3. 按 learning 的流程训练未掌握点，测即时闭卷回忆、实际应用与首次新场景迁移。记录辅助程度、答案暴露、实际训练时长和完成时间。
4. 从 `training_completed_at` 起安排第1、3、7、14、30天保持测试。这是效果测量日期，独立于按错误调整的学习复习队列。记录所有额外学习/复习，不能假装期间没有练习。
5. 每次先不看笔记做一道未见过的同等难度场景题，冻结该次原始分数，再反馈纠错。纠错后的重试另记，不能覆盖首次失败。
6. 未回复、暂停、漏测记为 pending/missed，不当作0分或成功；保存实际 elapsed_hours。超出预设窗口仍可测试，但标记 late，不能假装准时。
7. 收尾报告真实完成次数、首次闭卷分数、迁移得分、辅助率、错误复发及暴露情况。样本为一人时只描述该用户的变化，不声称普遍有效。

可以向用户请求提醒或使用其已授权的宿主自动化。提醒只提示参与，不代用户答题；每个阶段首次发出后等待，不每天重复催促。未完成T0/训练时不提前启动效果测量日期。

## 评分与问题变体

每个知识点0～4分：

- 0：无法回答或核心判断错误。
- 1：识别部分关键对象，核心流程仍不成立。
- 2：核心机制正确，重要边界或可操作步骤缺失。
- 3：独立给出可实施方案，覆盖本题关键失败边界。
- 4：在3分基础上处理新约束并解释可观察的取舍/验证办法。

辅助成功单独记录；闭卷独立分只用 assistance=none 且用户声明未看资料的首次尝试。评分规则是学习效果指标，不自动等同 mastery；Level4仍需要应用与迁移的证据。

Agent Memory默认3点：状态归属与隔离、检索与上下文预算、生命周期与恢复。每次换业务/任务/故障条件；不要重复原题或只换变量名。问题及参考评分点在作答前不展示答案。

## 最小状态

研究协议放 `studies/<study_id>/protocol.json`，真实试次追加 `trials.jsonl`；学习库的topics/error log仍使用原有脚本。协议包括：

- study_id、topic、knowledge_points、rubric_version、participant（匿名本地标识）
- status、baseline_completed_at、training_completed_at
- checkpoints（target_day、due_at、window_hours、status、question_id、notified_at）
- comparison（within-person before/after；是否启用等时匹配对照）

试次保存：实际时间、阶段、题目ID/场景、简短答案摘要、辅助程度、是否查看资料的声明、逐项评分与证据、实际elapsed_hours、额外复习暴露。只保存有学习价值的数据，不上传个人回答到公共仓库。

默认回访窗口为目标时间前后12小时；在训练完成前 due_at 为null。采用同一冻结评分规则并保留原始答案摘要，分数变化要能回溯到具体判断。

## 解释边界

前后测能显示变化；练习次数、题目难度、熟悉度与同期学习也会影响成绩。没有对照时不能将变化全部归因于Skill。

需要比较教学方法时，先做预测试以匹配知识点，再随机分到等时的主动学习与重读对照，使用等价新题、相同反馈和测量时间。记录交叉学习与测量本身的练习效应。少量知识点、单个用户的比较仍只作个人诊断，不宣称统计显著性或总体因果结论。
