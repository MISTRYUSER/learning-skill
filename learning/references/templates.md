# 按需交互模板

模板用于少量题的组织，不要求每轮输出全部栏目。任何答案/评分标准都在用户尝试前保持隐藏。

## 预测试与地图

开场：“先不看资料，试着回答这 3 个问题；不知道可以直接说不知道。”

问题组合：一个因果问题、一个关键流程/实践问题、一个边界或迁移问题。避免用题目暗示标准答案。

知识地图模板：

| 知识点 | 必要前置 | 独立通过标准 | 证据状态 |
|---|---|---|---|
| 本轮选定的小知识点 | 依赖点 ID 或无 | 可观察的回答/实现/判断 | 未评估、模糊、错误理解或已验证 |

地图 3～7 点，不等于每轮全测。能力证据以 mastery 与 assistance 为准。

## 问题卡（助手内部）

```json
{
  "question_id": "unique-id",
  "topic": "cache",
  "knowledge_point": "request-coalescing",
  "kind": "transfer",
  "scenario": "回源接口变为限流严格的第三方 API",
  "prompt": "设计缓存失效时的请求处理，并说明为什么。",
  "rubric": ["用户独立识别关键约束", "方案可处理失败", "说明取舍"],
  "evidence_ref": "用户回答摘要或沙盒验证记录"
}
```

不把 rubric 整体展示成答案；实践可先公开输入、约束和验收标准。

## 具体反馈

“你说的【具体正确点】成立，因为【证据】。但【具体错误/遗漏】会在【条件】导致【后果】。这属于【错误类型】。修正是【必要的局部解释】。接下来不看资料，用【不同条件】重试。”

Quiz 模式改为：“【具体点】通过；【具体点】未通过；【能力】仍待验证。”不主动显示纠正答案。表达不清时先请用户给例子或补足一步推理。

## 最小会话文件

```json
{
  "session_id": "unique-session-id",
  "topic": "cache",
  "mode": "learn",
  "phase": "closed_book_recall",
  "selected_points": ["request-coalescing"],
  "pending_question": {"id": "q2", "prompt": "如果回源请求超时，你的方案如何处理等待者？"},
  "verified": ["能够闭卷解释进程内请求合并"],
  "remaining": ["跨进程与超时边界待验证"],
  "updated_at": "2026-10-02T10:00:00+08:00"
}
```

仅保存当前待答题、进度与结论；一次会话一小份文件，不存完整聊天。独立评估事件使用 state.md 的格式，不由此模板制造评分。

## 收尾

- 已验证：具体知识点 + 独立完成的任务。
- 未验证：应用/迁移/保持能力的缺口。
- 下次：实际 next_review 日期（用户时区）。
- 继续：一道待答题或一个实践目标。

## 状态视图

`/status`：掌握点数 / 已评估点数，Level 分布，到期点数，保持待验证点数，当前待答任务。

`/weakness`：选 3～5 个优先点，给错误类型、最近证据与下一种练习；不要把缺少测试误写成能力差。

`/errors`：展示最近真实错误的用户答案摘要、纠正、复习时间和解决状态；避免泄漏私人源码。
